Лаб 5–6 — Мэдрэлийн сүлжээг эхнээс кодчилох

Энэ лабын гол зорилго нь backpropagation-ийг өөрийн гараар бичих. Гадны сан ашиглахгүйгээр давхарга бүрийн уламжлалыг гаргаж, PyTorch-той ижил үр дүн гарахыг батлана.

1. Linear давхарга — forward

class Linear:
    def forward(self, inp):
        self.inp = inp                        # backward-д хэрэгтэй тул хадгална
        self.z   = inp @ self.w + self.b      # z = xW + b
        return self.z
Яагаад оролтоо self.inp-д хадгалах ёстой вэ?
Жингийн уламжлал нь dW = xᵀ · dz. Өөрөөр хэлбэл оролт x уламжлалд шууд орж ирдэг. Forward дуусаад x-ээ хаячихвал backward хийх үед дахин тооцоолох шаардлага гарна. Тиймээс бүх framework (PyTorch, TensorFlow) энэ завсрын утгыг «computation graph»-даа хадгалдаг. Яг ийм учраас сургалт нь дүгнэлт (inference) хийхээс илүү их санах ой иддэг.

2. Linear давхарга — backward

    def backward(self, grads):
        # CELoss.backward аль хэдийн 1/m-ээр хуваасан тул энд ДАХИН хуваахгүй
        dw      = self.inp.T @ grads
        db      = grads.sum(axis=0, keepdims=True)
        da_prev = grads @ self.w.T
        return (da_prev, dw, db)
Яагаад энд / m хийхгүй вэ? (хамгийн их андуурдаг зүйл)
Дундаж алдагдал нь L = (1/m) Σᵢ Lᵢ. Тэр 1/m нь нэг л удаа орох ёстой. Манай кодонд түүнийг CELoss.backward дотор хийсэн. Хэрэв Linear дотор дахин хуваавал бодит градиент 1/m² дахин багасна — m = 60 000 үед энэ нь градиентийг 60 000 дахин жижигрүүлж, сүлжээ бараг огт суралцахгүй болно.

Багшийн эх кодонд m = self.inp.shape[1] гэж бичсэн нь бас алдаатай: shape[1] нь шинжийн тоо (784) болохоос багцын хэмжээ биш. Зөв нь shape[0].

3. Sigmoid ба тоон тогтвортой байдал

class Sigmoid:
    def forward(self, inp):
        self.out = 1.0 / (1.0 + np.exp(-np.clip(inp, -500, 500)))
        return self.out
    def backward(self, grads):
        s = self.out
        return grads * s * (1 - s)        # σ'(z) = σ(z)(1−σ(z))
Яагаад np.clip(inp, -500, 500) хэрэгтэй вэ?
np.exp(800) нь float64-ийн багтаамжаас хальж inf болно. Дараа нь 1/(1+inf) = 0 гарч, цааш log(0) = -inf → бүх алдагдал NaN болно. Нэг л NaN гарвал тэр нь үржүүлэг бүрээр тархаж, сүлжээ бүхэлдээ сүйрнэ.

±500 дээр таслах нь утгыг гажуудуулахгүй: σ(500) ба σ(∞) хоёрын зөрүү нь 10⁻²¹⁷ орчим, float-ийн нарийвчлалаас хамаагүй жижиг.

4. Cross-entropy алдагдал

class CELoss:
    def forward(self, pred, target):
        self.yhat = np.clip(pred, 1e-12, 1-1e-12)     # log(0)-оос хамгаална
        self.y = target
        m = self.y.shape[0]
        return -np.sum(self.y*np.log(self.yhat)
                       + (1-self.y)*np.log(1-self.yhat)) / m

Багшийн эх кодон дахь тэмдгийн алдаа

Эх хувилбарт loss = (-term1 + term2) / m гэж бичигдсэн байв. Зөв нь -(term1 + term2). Хоёр дахь гишүүний тэмдэг буруу байсан тул алдагдлын утга утгагүй болдог. Сонирхолтой нь backward нь зөв томьёогоор бичигдсэн байсан — өөрөөр хэлбэл forward ба backward хоёр нь хоорондоо зөрчилдөж байсан.
Эх сурвалж
Goodfellow, Bengio, Courville — Deep Learning (MIT Press, 2016), 6.2.1.1: cross-entropy ба maximum likelihood-ийн хамаарал.
He et al., Delving Deep into Rectifiers (ICCV 2015) — He initialization, доорх сайжруулалтад ашигласан.

Яагаад ийм том ялгаа гарсан бэ? (3 шалтгаан)
1. Жингийн эхлэл. Багшийн код жинг жижиг санамсаргүй тоогоор эхлүүлдэг. Давхарга бүрт дохио багасч, 3 дахь давхаргад бараг тэг болно («vanishing signal»). He initialization нь дисперсийг 2/n_in болгож, дохиог давхарга дамжин тогтвортой байлгана.

2. Softmax + cross-entropy-г НЭГТГЭХ. Тусад нь бодвол σ'(z) үржигдэж градиент сулардаг. Нэгтгэвэл уламжлал нь (p − y)/m гэсэн маш энгийн хэлбэртэй болж, σ' огт орохгүй — тиймээс ханалтаас (saturation) болж градиент үхэхгүй.

3. Mini-batch SGD. Бүх 60 000 дээжээр нэг алхам хийхийн оронд 64-өөр хувааж олон алхам хийнэ. Нэг epoch-д 1 биш ~937 шинэчлэл болно.
График хэрхэн харагдах ёстой вэ?
Loss муруй: эхэндээ огцом буурч, дараа нь тэгширнэ — хажуу тийш харсан «тохой» (elbow) хэлбэр. Энэ нь зөв. Эхэндээ жин санамсаргүй учир алдаа их, оновчлол хурдан сайжруулна; сүүлдээ хамгийн доод цэгт ойртох тусам ахиц багасна.

Хэрэв loss шулуун доошоо унаж тэгширэхгүй бол — хараахан дуусаагүй, илүү олон epoch хэрэгтэй.
Хэрэв loss дээш үсэрч эхэлбэл — сургалтын хурд хэт их (бидний туршилтад lr=0.5 дээр яг ийм зүйл болж accuracy 0.0991 хүртэл унасан — өөрөөр хэлбэл санамсаргүй таамаглалтай тэнцсэн).
Accuracy муруй нь эсрэгээрээ: хурдан дээшилж, дараа нь хавтгайрна. Хавтгайрсан хойно үргэлжлүүлэх нь ашиггүй.

1. Яагаад sigmoid-ийг авч хаясан бэ?

x = self.fc3(x)
# CrossEntropyLoss нь дотроо log_softmax хийдэг тул ТҮҮХИЙ logit хүлээдэг.

Яагаад sigmoid нь энд саад болдог вэ?
nn.CrossEntropyLoss нь оролт дээрээ log_softmax-ийг өөрөө хэрэглэдэг. Урьдчилж sigmoid тавихад:
  • Гаралт (0, 1) завсарт шахагдана → ангиудын хоорондох зөрүү багасна.
  • Softmax нь зөрүүгээс хамаардаг тул магадлалууд бүгд 0.1-д ойртоно.
  • Нэмж sigmoid-ийн уламжлал σ(1−σ) ≤ 0.25 нь градиентийг дахин сулруулна.
Үүнийг батлахын тулд би sigmoid-ийг grid search-ийн нэг параметр болгосон. Үр дүн: дөрвөн хос тохиргоо бүрт sigmoid-гүй хувилбар давуу гарсан (дунджаар +1.3 оноо). Нэг тохиолдол бол санамсаргүй байж болох ч 4/4 бол тогтмол.

Багшийн evaluate_model нь тестийн accuracy-гаар best_model.pth хадгалдаг, мөн hyperparameter-ээ тестээр шалгаруулдаг. Ингэснээр тестийн мэдээлэл сонголтод нэвтэрч, эцсийн тоо бодит чадвараас өндөр гарна.
Яг ямар хэмжээний хазайлт гарах вэ? (notebook дотор тоогоор хэмжсэн)

3. AUC гэж юу вэ, яагаад accuracy-гаас өндөр байдаг вэ?

AUC-ийн утга (энгийнээр)
AUC нь санамсаргүй сонгосон зөв жишээг санамсаргүй сонгосон буруу жишээнээс илүү өндөр оноогоор эрэмбэлэх магадлал. Өөрөөр хэлбэл энэ нь эрэмбийг хэмждэг болохоос шийдвэрийн босгыг хэмждэггүй.

Тиймээс загвар зөв ангийг хамгийн өндөр магадлалаар тавьж чаддаг ч босго нь бага зэрэг хазайсан бол accuracy буурна, AUC өндөр хэвээр үлдэнэ. Манай олон ангиллын тохиолдолд multi_class="ovr" (нэг эсрэг бусад) хэлбэрээр анги бүрт тооцоод дунджийг нь авна.
Confusion matrix-ийг хэрхэн унших вэ?
Диагональ нь зөв таамаглал — хамгийн тод байх ёстой. Диагоналиас гадуурх тод нүд бүр нь «жинхэнэ i-г j гэж андуурсан» гэсэн үг.

Манай үр дүнд хамгийн нягт хос нь 5 → 3, дараа нь 4 → 9. Энэ нь сайн шинж: загвар санамсаргүй биш, бичгийн хувьд үнэхээр төстэй цифрүүдийг андуурч байна. Хэрэв 0 ба 1 зэрэг огт өөр цифрүүд хоорондоо андуурагдаж байвал өгөгдөл эсвэл шошгонд асуудал байна гэсэн үг.

1. Stacking дахь хоёр дахь leakage

Meta загварыг яагаад out-of-fold таамаглалаар сургах ёстой вэ?
Суурь загварууд x_train дээр сурсан. Дараа нь яг тэр мөрүүд дээрээ таамаг гаргавал тэд хэт сайн таамагладаг (зарим нь цээжилсэн). Meta загвар тэр «хэт цэвэрхэн» оролтыг хараад сурдаг.

Гэтэл тест үед суурь загварууд хараагүй мөрүүд дээр таамаглах тул чанар нь доогуур байна. Өөрөөр хэлбэл meta загвар нэг тархалт дээр сурчихаад өөр тархалт дээр ажиллах болно.

Out-of-fold: өгөгдлийг K хэсэг болгож, хэсэг бүрийн таамгийг түүнийг хараагүй загвараар гаргана. Ингэснээр meta загварын оролт нь тестийн үеийнхтэй ижил чанартай болно.

Бидний хэмжилтээр энэ засвар нь 0.851 → 0.870 болгож, алдагдсан ~2 оноог нөхсөн.

Лаб 9–10 — Knowledge Distillation (мэдлэг дамжуулах)

Санаа: том, хүчтэй загвар (teacher)-аас жижиг, хурдан загвар (student) руу мэдлэг дамжуулах. Жижиг загварыг шууд сургахаас илүү сайн үр дүн гарна.

1. Яагаад «зөөлөн шошго» нь жинхэнэ шошгоос илүү мэдээлэлтэй вэ?

Dark knowledge гэж юу вэ?
Жинхэнэ шошго нь «энэ бол 7» гэж л хэлнэ. Багшийн гаралт нь үүнээс илүүг хэлдэг: «95% магадлалтай 7, 4% магадлалтай 1, 0.9% магадлалтай 9, 0.01% магадлалтай 0».

Энэ харьцангуй магадлалууд нь ангиудын хоорондох төстэй байдлын бүтцийг агуулж байна — 7 нь 1-тэй төстэй, 0-тэй огт төстэй биш. Hinton үүнийг «dark knowledge» гэж нэрлэсэн. Оюутан энэ бүтцийг сурснаар ердөө «зөв хариулт»-аас илүү зүйл авна.

Температур T: softmax-ийг z/T дээр хэрэглэвэл магадлалын тархалт тэгширнэ — жижиг магадлалууд (0.01%) мэдэгдэхүйц болно. Тиймээс distillation-д T > 1 хэрэглэдэг.

2. Даалгавар: «дундаас нь» мэдлэг дамжуулах = FitNets

Багшийн даалгавар нь «Teacher болон Student загварын дундаас нь мэдлэгийг дамжуулах». Logit-distillation нь зөвхөн эцсийн шийдвэрийг дамжуулдаг. FitNets нь завсрын давхаргын дүрслэлийг дамжуулна.

# 1. Багшийн завсрын гаралт (hint)
ep = Teacher.extract_endpoints(xb)
hint = F.adaptive_avg_pool2d(ep["reduction_4"], 1).flatten(1)   # 112 хэмжээст

# 2. Оюутны дунд давхарга + хэмжээг тааруулах regressor
h2  = F.relu(self.bn2(self.fc2(h1)))      # 800 хэмжээст
hs  = self.reg(h2)                          # 800 → 112

# 3. 1-р шат: зөвхөн дунд давхаргыг ойртуулна
loss = F.mse_loss(hs, hint)
Яагаад reduction_4-ийг сонгосон бэ?
EfficientNet-B0 нь 6 завсрын гаралттай: reduction_1 (16 суваг) … reduction_6 (1280 суваг).
  • reduction_1/2 — ирмэг, өнцөг зэрэг хэт энгийн шинж. Оюутанд дамжуулах мэдлэг бага.
  • reduction_5/6 — аль хэдийн ангиллын шийдвэрт маш ойр. Эдгээрийг дамжуулах нь logit-distillation-тай давхцана, шинэ зүйл өгөхгүй.
  • reduction_4 (112 суваг) — сүлжээний дунд. Даалгаврын «дундаас нь» гэсэн шаардлагад яг нийцнэ.
Яагаад regressor хэрэгтэй вэ?
Багшийн hint нь 112 хэмжээст, оюутны дунд давхарга нь 800 хэмжээст. Хоёрыг шууд харьцуулах боломжгүй. FitNets нь оюутан дээр нэмэлт шугаман давхарга (regressor) тавьж 800 → 112 буулгана.

Чухал нь: энэ regressor нь зөвхөн сургалтын үед хэрэглэгдэнэ. Сургаж дууссаны дараа түүнийг хаяна — оюутны эцсийн бүтэц өөрчлөгдөхгүй, хурд нь хэвээр.
Эх сурвалж
Hinton, Vinyals, Dean — Distilling the Knowledge in a Neural Network, NIPS 2014 Deep Learning Workshop (arXiv:1503.02531).
Romero, Ballas, Kahou, Chassang, Gatta, Bengio — FitNets: Hints for Thin Deep Nets, ICLR 2015 (arXiv:1412.6550). 3-р хэсэгт hint/guided давхарга, regressor-ийн тодорхойлолт.
Яагаад багшийн гаралтыг урьдчилж тооцоолсон бэ?
Багш нь хөлдөөстэй (жин нь өөрчлөгдөхгүй) бөгөөд өгөгдөл дээр санамсаргүй өөрчлөлт (augmentation) хийхгүй. Тиймээс нэг зураг дээрх багшийн гаралт epoch бүрт яг ижил байна.

Эдгээрийг нэг удаа тооцоолоод санах ойд хадгалснаар 4 хувилбар × 15 epoch = 60 удаагийн илүүц тооцооллыг арилгана. Энэ нь үр дүнг огт өөрчлөхгүй, зөвхөн хурдасгана.

Анхаар: хэрэв augmentation байсан бол энэ оновчлол буруу болно — зураг epoch бүрт өөрчлөгддөг тул багшийн гаралт ч өөр байх ёстой.

Үр дүн

Дөрвөн хувилбарын харьцуулалт (оюутан ганцаараа / багшийн KD / засварласан KD / FitNets) Colab дээр ажиллаж дууссаны дараа бичигдэнэ. Механизм нь жижиг хэмжээнд 0 алдаатай шалгагдсан.

1. Яагаад эхлээд TF-IDF суурь загвар хийх ёстой вэ?

Суурь загварын үүрэг

Энэ бол судалгааны ажлын үндсэн зарчим: хямд шийдлийг эхлээд туршина.

3. Алдааны ангилал (Даалгавар 5)

def categorize(i, r):
    if i in fixed:       return "1. Таслалтаас"              # head+tail засдаг
    if r["p1"] > 0.90:  return "2. Шошгын алдаа (сэжигтэй)"  # confident learning
    if r["gap"] < 0.25: return "3. Олон сэдэвт"
    return "4. Загварын алдаа"
Энэ логикийн үндэслэл
1. Хэрэв head+tail хувилбар уг жишээг зөв таасан бол анхны алдаа нь таслалтаас байсан нь тодорхой.

2. Загвар 90%-иас дээш итгэлтэйгээр шошгоос өөр хариулт өгсөн бол шошго нь буруу байх магадлал өндөр. Энэ нь confident learning-ийн үндсэн зарчим: загварын өндөр итгэл + шошготой зөрөх = шошгын алдааны дохио.

3. Эхний хоёр магадлалын зөрүү (gap) бага байна гэдэг нь загвар хоёр ангийн хооронд эргэлзэж байна гэсэн үг — мэдээ үнэхээр олон сэдэвт байж магадгүй. Энэ нь таны эрдэм шинжилгээний сэдэвтэй шууд холбоотой.

4. Үлдсэн нь жинхэнэ загварын алдаа.
Сургалтын график хэрхэн харагдах ёстой вэ?
Train loss: тасралтгүй буурна.
Validation loss: эхлээд буурч, дараа нь тэгширнэ. Хэрэв validation loss дээш эргэж эхэлбэл — хэт тохирол (overfitting) эхэлсэн, тэр цэгт зогсоох ёстой.

Fine-tuning-д epoch цөөн (2–3) байдаг нь санамсаргүй биш: BERT аль хэдийн урьдчилан сургагдсан тул хэт удаан сургавал тэр мэдлэгээ «мартаж» эхэлдэг (catastrophic forgetting).

Анхаар: графикийн нүд хоосон байвал (log_history хоосон) энэ нь logging_steps хэт том байсан эсвэл сургалт таслагдсаны шинж — notebook дотор түүнийг шалгаад алгасдаг болгосон.

Бүх засвар нь нэг бүрчлэн тайлбартай, notebook дотор яг тэр мөрний дэргэд бичигдсэн. Засвар бүрийн ард хэмжсэн нотолгоо байгаа:

Багшийн тоо нь тестийг олон удаа хэмжээд хамгийн сайныг нь авсан үр дүн. Миний тоо нь validation-аар сонгоод тестэд нэг л удаа хүрсэн үр дүн. Эхнийх нь өндөр гарах нь зүй ёсны — гэхдээ шинэ өгөгдөл дээр давтагдахгүй. Notebook дотор энэ зөрүүг тоогоор хэмжиж харуулсан.

Хэрэв «ensemble яагаад тусалсангүй вэ?» гэж асуувал

Энэ нь алдаа биш, хүлээгдэж буй үр дүн. Санал зөрөх хувийг хэмжсэн (8.9–10.3%) — суурь загварууд ижил алдаа гаргадаг. Харин bagging/RandomForest нь ганц модноос +8 оноо өгсөн, өөрөөр хэлбэл ensemble-ийн зарчим ажиллаж байгаа, зүгээр л зөв нөхцөлд ажилладаг.
Бүх тоо энэ хичээлийн notebook-уудыг биечлэн ажиллуулж гаргасан. «Colab дээр гарна» гэж тэмдэглэсэн хэсгүүдэд тоо бичээгүй — ажиллаагүй үр дүнг урьдчилан бичихгүй.
